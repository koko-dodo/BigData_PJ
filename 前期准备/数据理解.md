# 第四题：时间序列异常检测——数据理解

## 1. 我们到底在做什么？

本项目的目标是：

> 从大规模监控指标中自动发现异常时间序列。

简单来说，假设一个大型电商网站正在运行，系统中有：

- 前端服务（Frontend）
- 商品服务（Product Catalog）
- 购物车服务（Cart）
- 支付服务（Payment）
- 推荐服务（Recommendation）
- 广告服务（Ad）

以及运行这些服务的基础设施组件：

- 服务器（Node）
- 容器（Container）
- JVM（Java 虚拟机）
- Istio 服务网格

这些组件会持续产生监控数据，例如：

```text
CPU 利用率
内存占用
GC 次数
请求量
响应时间
网络流量
```

项目要求自动找出：

```text
哪些指标出现异常？
什么时候出现异常？
```

## 3. 数据分为哪几类？

每个场景下都有：

```text
metric/
├── service
├── node
├── container
├── jvm
└── istio
```

### 3.1 service

业务层指标，记录请求成功率、响应时间、请求数量等。

例如：

```csv
service,timestamp,rr,sr,mrt,count
adservice-grpc,1647716400,100.0,100.0,2.43,61
```

字段含义：

| 字段 | 含义 |
| --- | --- |
| service | 服务名称 |
| timestamp | 时间戳 |
| rr | 响应率 |
| sr | 成功率 |
| mrt | 平均响应时间 |
| count | 请求数 |

### 3.2 node

物理机或虚拟机指标。

例如：

```csv
timestamp,cmdb_id,kpi_name,value
1647792000,node-4,system.load.5,0.65
```

表示：

```text
node-4 机器的 5 分钟平均负载 = 0.65
```

### 3.3 container

容器指标。

例如：

```csv
timestamp,cmdb_id,kpi_name,value
1647813600,node-5.paymentservice-1,container_network_receive_packets_dropped.eth0,0.0
```

表示：

```text
paymentservice 容器丢包数 = 0
```

### 3.4 jvm

Java 虚拟机指标。

例如：

```csv
timestamp,cmdb_id,kpi_name,value
1647828000,adservice.ts:8088,java_nio_BufferPool_TotalCapacity.direct,57343
```

表示：

```text
广告服务 JVM Direct Buffer 容量 = 57343
```

### 3.5 istio

服务网格指标。

例如：

```csv
timestamp,cmdb_id,kpi_name,value
1647828000,istio-egressgateway-xxx,istio_agent_startup_duration_seconds,40.8
```

表示：

```text
Istio 组件启动耗时 = 40.8 秒
```

## 4. 什么是一条时间序列？

这是整个项目最重要的概念。

监控数据统一格式为：

```csv
timestamp,cmdb_id,kpi_name,value
```

其中：

```text
cmdb_id + kpi_name
```

唯一确定一条时间序列。

例如：

```text
(node-4, system.load.5)
```

形成：

```text
时间     值
08:00   0.65
08:01   0.69
08:02   0.68
08:03   0.74
...
```

这就是一条时间序列。

---

## 5. 为什么老师说有 5000+ 序列？

一开始我们以为：

```text
一个 CSV = 一条序列
```

后来发现不对。统计结果如下：

```text
container : 5417
jvm       : 667
istio     : 2252
node      : 354
----------------
总计      : 8690
```

因此：

```text
项目实际包含约 8690 条时间序列
```

远超老师要求的：

```text
5000+
```

## 6. 采样频率是多少？

观察数据：

```text
1647792000
1647792060
1647792120
1647792180
```

时间戳每次增加：

```text
60 秒
```

因此：

```text
采样频率 = 60 秒
```

与题目要求完全一致。

---

## 7. 一条序列有多长？

统计发现：

```text
(node-4, system.load.5)
```

共有：

```text
1440 个点
```

因为：

```text
24 小时 × 60 分钟 = 1440
```

所以：

```text
每条时间序列覆盖一天数据
```

---

## 8. 后续异常检测的对象是什么？

异常检测不是针对：

```text
CSV 文件
```

而是针对：

```text
(cmdb_id, kpi_name)
```

对应的时间序列。

例如：

```text
(node-4, system.load.5)
```

或者：

```text
(paymentservice-1, container_cpu_usage_seconds_total)
```

---

## 9. 我们后面要做什么？

整体流程：

```text
HDFS
↓
Spark 读取数据
↓
构造 8690 条时间序列
↓
异常检测（IQR 等方法）
↓
发现异常时间点
↓
输出异常指标
```

最终目标：

```text
找出哪些指标异常，以及异常发生的时间
```

而不是简单统计均值或画图。
