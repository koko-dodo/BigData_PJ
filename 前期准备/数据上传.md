# 数据上传

## 本阶段目标

将老师提供的训练数据导入 Hadoop 集群，为后续 Spark 数据分析与异常检测做准备。

- HDFS 地址：`hdfs://master:9000`
- 项目数据目录：`/aiops/metric`

---

## 数据情况

原始数据：

```text
metric.zip
```

解压后目录：

```text
metric/
├── 2022-03-20-cloudbed1
├── 2022-03-20-cloudbed2
├── 2022-03-20-cloudbed3
├── 2022-03-21-cloudbed1
├── 2022-03-21-cloudbed2
└── 2022-03-21-cloudbed3
```

每个场景包含：

```text
metric/
├── service
├── node
├── container
├── jvm
└── istio
```

数据规模：

```text
解压后约 3.5GB
文件总数约 1433 个
```

## 已完成工作

### 1. 数据上传到 Master 节点

将本地数据上传至 Master 节点：

```text
/root/metric
```

验证数据大小：

```bash
du -sh metric
```

输出：

```text
3.5G metric
```

说明数据完整。

---

### 2. 创建 HDFS 项目目录

执行：

```bash
hdfs dfs -mkdir -p /aiops
```

创建项目数据目录。

---

### 3. 上传数据到 HDFS

执行：

```bash
hdfs dfs -put metric /aiops/
```

上传过程耗时较长，约十几分钟。期间出现以下日志：

```text
Slow waitForAckedSeqno
Slow ReadProcessor
```

经确认，该日志属于 HDFS 副本同步速度较慢的提示，不是报错，不影响上传结果。

---

### 4. 验证上传成功

查看 HDFS 目录占用：

```bash
hdfs dfs -du -h /aiops
```

结果：

```text
3.5 G  7.0 G  /aiops/metric
```

说明：

- 原始数据约 3.5GB。
- HDFS 实际占用约 7.0GB。
- 与 `dfs.replication = 2` 的配置一致。

查看上传后的目录：

```bash
hdfs dfs -ls /aiops/metric
```

结果包含：

```text
2022-03-20-cloudbed1
2022-03-20-cloudbed2
2022-03-20-cloudbed3
2022-03-21-cloudbed1
2022-03-21-cloudbed2
2022-03-21-cloudbed3
```

说明六个实验场景均已成功进入 HDFS。

## 注意事项

### 1. 不要再次上传同一份数据

如果再次执行：

```bash
hdfs dfs -put metric /aiops/
```

可能产生重复目录，或报文件已存在。

建议先查看：

```bash
hdfs dfs -ls /aiops
```

确认后再操作。

---

### 2. 不要删除 HDFS 数据目录

当前项目所有后续分析均依赖：

```text
/aiops/metric
```

请勿执行：

```bash
hdfs dfs -rm -r /aiops/metric
```

---

### 3. HDFS 副本数

当前配置：

```text
dfs.replication = 2
```

因此：

```text
3.5GB 数据 ≈ 7GB 实际存储
```

属于正常现象。

---

### 4. 上传时出现 Slow ReadProcessor 不必紧张

出现：

```text
Slow waitForAckedSeqno
Slow ReadProcessor
```

属于 DataNode 副本确认较慢。

只要没有出现以下信息，一般都不是故障：

```text
ERROR
FAILED
IOException
```
