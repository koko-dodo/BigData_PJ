# 平台与处理架构

## 原实验环境

| 组件 | 课程记录 |
|---|---|
| 节点 | 1 个 Master、2 个 Worker；每台 8 核、16GB 内存 |
| 操作系统 | CentOS 7 |
| Hadoop | 3.3.6；HDFS 副本数 2 |
| Spark | 3.5.1 / Scala 2.12 |
| Java | OpenJDK 8 |

以上是历史复现基线，不是新部署环境的版本推荐。

清洗阶段根据原交付说明使用 `local[*]`，通过 Spark 读取和写回 HDFS。异常检测阶段使用 Spark Standalone。环境搭建时做过 YARN 测试，不应将整个检测流程描述为运行于 YARN。

## 数据流

1. 六个日期/场景目录中的五类 CSV 上传到 HDFS。
2. 清洗脚本统一字段、类型和表结构，按指标类型存储 Parquet。
3. V1—V4 分别读取同一清洗结果，各自独立执行；V3/V4 不依赖前一版本的异常输出。
4. 检测结果写入独立目录，后续分析从物化结果读取，避免反复计算完整上游流程。

## 执行策略

- V1/V2 按对象和 KPI 重新分区后做分组聚合与回连。
- V2 缓存统计表和打分结果；V3 缓存窗口打分结果；V4 缓存输入、宽表与结果。
- 使用 `MEMORY_AND_DISK` 在重用与内存压力之间折中。
- V2 的全类型入口默认按类型设置 16/32/64 个 shuffle 分区；显式 `SHUFFLE_PARTITIONS` 会覆盖这些默认值。
- 检测、汇总和展示分开执行；没有保存前后耗时基准，因此不报告加速倍数。
